1. Docker Compose, c’est quoi ?

Docker Compose permet de décrire et gérer plusieurs conteneurs dans un seul fichier, généralement compose.yaml. Un Dockerfile explique comment construire une image ; compose.yaml explique comment les images et conteneurs fonctionnent ensemble.

ÉlémentRôle
DockerfileRecette de construction d’une image.
ImageModèle immuable contenant l’application et ses dépendances.
ConteneurInstance en cours d’exécution d’une image.
compose.yamlDescription des services, ports, variables, réseaux et volumes.
Projet ComposeGroupe logique de tous les conteneurs et réseaux de l’application.
Docker Desktop peut afficher une ligne bankaccount contenant deux lignes enfants. Ce n’est pas un conteneur avec des sous-conteneurs : c’est un groupe visuel contenant deux conteneurs indépendants.

Accès direct : localhost:5000 → backend:5000

Compose crée automatiquement un réseau privé. Les services se trouvent par leur nom : le frontend peut appeler http://backend:5000. En revanche, le navigateur de l’utilisateur ne connaît pas le nom Docker backend ; Nginx sert donc de proxy pour les requêtes /api.

3. Exemple complet de compose.yaml

name: bankaccount

services:
  backend:
    image: ${DOCKERHUB_USERNAME}/bankaccount-services:${IMAGE_TAG:-latest}
    build:
      context: ../BankAccountServices
      dockerfile: Dockerfile
    environment:
      ASPNETCORE_ENVIRONMENT: Development
      ConnectionStrings__DBConnection: ${DB_CONNECTION}
      Jwt__Key: ${JWT_KEY}
      Jwt__Issuer: ${JWT_ISSUER}
      Jwt__Audience: ${JWT_AUDIENCE}
      S3__BucketName: ${S3_BUCKET_NAME:-lambdacomp}
      S3__Region: ${S3_REGION:-us-east-1}
    ports:
      - "5000:5000"
    restart: unless-stopped

  frontend:
    image: ${DOCKERHUB_USERNAME}/bankaccount-front:${IMAGE_TAG:-latest}
    build:
      context: .
      dockerfile: Dockerfile
    depends_on:
      - backend
    ports:
      - "8080:80"
    restart: unless-stopped
Cohérence des noms : si le service s’appelle backend, Nginx doit utiliser proxy_pass http://backend:5000;. S’il s’appelle api, Nginx doit utiliser http://api:5000.

4. Explication de chaque clé

CléRéférence / effet
nameNom du projet et du groupe dans Docker Desktop. Sert aussi de préfixe aux ressources.
servicesListe des applications gérées par Compose.
backend, frontendNoms choisis pour les services. Ils servent dans les commandes et comme noms DNS sur le réseau interne.
imageNom et tag de l’image locale ou Docker Hub : utilisateur/image:tag.
buildDemande de construire l’image avec un Dockerfile.
contextDossier envoyé au moteur Docker. . = dossier actuel ; .. = dossier parent.
dockerfileNom du Dockerfile relatif au contexte de build.
environmentVariables injectées dans le conteneur.
portsPublication sous la forme port_machine:port_conteneur.
depends_onDémarre le service référencé avant l’autre. Ne garantit pas que l’application soit déjà prête.
restartPolitique de redémarrage. unless-stopped redémarre sauf arrêt manuel.

5. Comprendre la syntaxe YAML

  • L’indentation crée la hiérarchie. Utiliser des espaces, pas des tabulations.
  • : associe une clé à une valeur : name: bankaccount.
  • - ajoute un élément à une liste, par exemple un port.
  • . représente le dossier courant et .. son parent.
  • ${JWT_KEY} lit une variable depuis l’environnement ou le fichier .env.
  • ${IMAGE_TAG:-latest} utilise latest si IMAGE_TAG est absent ou vide.
services:             # niveau 1
  backend:            # appartient à services
    ports:            # appartient à backend
      - "5000:5000"   # élément de la liste ports

6. Ports et réseau

ports:
  - "5000:5000"
#    machine:conteneur
DéclarationRésultat
"5000:5000"http://localhost:5000 est transmis au port 5000 du backend.
"8080:80"http://localhost:8080 est transmis au port 80 de Nginx.
http://backend:5000Adresse interne utilisable uniquement entre les conteneurs du réseau Compose.
Dans un conteneur, localhost désigne ce conteneur lui-même. Pour joindre MySQL installé sur Windows, utiliser généralement host.docker.internal.

7. Variables et fichier .env

DOCKERHUB_USERNAME=mon-utilisateur
IMAGE_TAG=latest
DB_CONNECTION=Server=host.docker.internal;Port=3306;Database=bankaccount;User=user;Password=secret
JWT_KEY=une-cle-secrete-d-au-moins-32-caracteres
JWT_ISSUER=BankAccountServices
JWT_AUDIENCE=BankAccountFront
S3_BUCKET_NAME=lambdacomp
S3_REGION=us-east-1

Le fichier .env se place à côté de compose.yaml et ne doit pas être envoyé sur Git. Dans ASP.NET Core, le double underscore représente une section : Jwt__Key correspond à Jwt:Key dans la configuration JSON.

Ne jamais publier de vrais mots de passe, clés JWT ou clés cloud dans Docker Hub, Git ou une capture d’écran.

Exécuter les commandes depuis le dossier contenant compose.yaml :

cd C:\Users\ihebb\source\repos\BankAccountFront
CommandeAction

docker compose buildConstruit toutes les images.

Avec les noms configurés dans image, Compose publie :

mon-utilisateur/bankaccount-services:latest
mon-utilisateur/bankaccount-front:latest

Sur une autre machine :

docker login
docker compose pull
docker compose up -d --no-build

10. Développement, production et Swagger

Le backend active Swagger uniquement si son code contient la condition suivante et que l’environnement vaut Development :

if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

Pour le développement local :

ASPNETCORE_ENVIRONMENT: Development
# Swagger : http://localhost:5000/swagger/index.html

Pour la production :

ASPNETCORE_ENVIRONMENT: Production

Swagger reste alors désactivé, mais la route de santé reste disponible sur http://localhost:5000/health.

11. Dépannage rapide

ProblèmeCause / vérification
Missing Jwt:Key.env absent, mal nommé ou JWT_KEY vide. Recréer avec docker compose up -d --force-recreate.
Swagger retourne 404Le backend est en Production. Passer temporairement en Development.
Frontend ne joint pas l’APIVérifier que le nom dans proxy_pass correspond exactement au nom du service.
Connexion MySQL refuséeNe pas utiliser localhost pour MySQL sur Windows ; essayer host.docker.internal et vérifier le port.
Port déjà utiliséChanger le port machine, par exemple "5001:5000".
Ancienne configuration conservéedocker compose down, puis docker compose up -d --build --force-recreate.
docker compose config
docker compose ps
docker compose logs -f backend
docker compose logs -f frontend
